# Geminiワーカー

ローカルで認証済みのAntigravity CLIを、Codexが計画した作業を実行するワーカーとして
使う。計画、要件の解釈、設計判断、作業範囲の決定、最終レビューはCodexが担う。
Geminiには具体的な作業項目と完了条件を渡し、その範囲での変更と指定した検証だけを
行わせる。モデルは`gemini-3.8-flash-high`に固定する。別のモデルを選んだり、別の
コマンドで`agy`を起動したりしない。付属スクリプトはファイル編集を許可する
`accept-edits`モードを指定するが、権限を一括許可するオプションは使わない。

## 手順

1. Codexが先に計画を立て、委譲する作業項目を決める。Geminiに計画、要件整理、設計案
   の比較、タスク分解をさせない。
2. 対象ファイル、具体的な変更内容、維持する条件、実行してよい検証、完了条件を明記
   する。無関係な会話、認証情報、秘密情報、不要な個人情報は渡さない。
3. 対象リポジトリのルートから、このスキルのディレクトリにある付属スクリプトを使い、
   作業指示を標準入力から渡す。スクリプトは呼び出し元のディレクトリを`--add-dir`で
   workspaceに追加するため、Codexのワークツリーも対象として扱える。これは作業対象の
   workspace指定であり、コマンド実行などの権限を一括許可するものではない。

   ```sh
   cat <<'PROMPT' | <gemini-workerスキルのディレクトリ>/scripts/run-gemini-worker.sh
   作業項目: <Codexが計画した具体的な変更>
   対象: <変更してよいファイルや範囲>
   条件: <維持すること、変更しないこと>
   検証: <実行してよい確認>
   完了条件: <期待する変更と報告内容>
   PROMPT
   ```

4. 作業後、変更ファイル、実施した検証、その結果を報告させる。モデルの報告だけで完了
   とせず、Codexが実際の差分と検証結果を確認する。空の応答や権限拒否は未完了として扱う。
5. 指示が曖昧、矛盾、または対象範囲外の変更が必要なら、推測で進めずCodexへ確認を
   返させる。認証、利用枠、タイムアウト、権限の問題もそのまま報告させる。

## 委譲する作業の範囲

- Codexが計画した、範囲の明確な実装・修正作業に使う。
- Antigravityの権限設定で許可された場合、指定対象のファイルを作成・編集できる。
  コマンドもCodexの計画に明記され、設定で許可されたものだけ実行できる。
- 依頼にないファイル変更、設計変更、未指定のコマンド、外部への操作はしない。
- Geminiに計画を作らせたり、追加タスクを自分で考えさせたりしない。手順が不明なら
  Codexへ質問を返す。
- Codexが差分と検証結果を確認し、作業の採否と最終回答を決める。
- ユーザーの依頼とリポジトリの指示を優先する。

## 付属スクリプト

標準入力からUTF-8の作業指示を一つ受け取り、完了した返答だけを標準出力へ返す。
呼び出し元のディレクトリをworkspaceとして明示し、`gemini-3.8-flash-high`と
`accept-edits`を指定して`agy`のJSONストリームを処理する。ヘッドレス実行では権限拒否が
終了コード0でも標準エラーへ通知されるため、その拒否通知、CLIエラー、空の応答を検出
した場合は失敗として終了する。操作の権限は既存のAntigravity設定に従い、
`--dangerously-skip-permissions`は使わない。
