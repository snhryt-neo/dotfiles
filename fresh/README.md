# fresh

## Overview

ターミナルエディタ [fresh](https://getfresh.dev/) の設定。`mise.toml` の定義により、このディレクトリが `~/.config/fresh` へディレクトリごとシンボリックリンクされる。fresh 本体は設定 UI やコマンドパレットからの変更を同じパスへ書き戻すため、リポジトリ内の実体が直接更新される。

## ADR

### 設定をファイル単位ではなくディレクトリ単位でリンクする

fresh は設定の保存時、同じディレクトリに一時ファイルを書いてから `rename` で差し替える（`crates/fresh-editor/src/config_io.rs`）。`rename` はパス名を新しい inode へ張り替える操作なので、`config.json` 単体を指すリンクは保存のたびに実ファイルへ置き換わり、リポジトリとの結び付きが切れる。

#### その他の検討パターン

| パターン概要 | 採用 | 保存後もリンクが持続 | 破損に気付けるか | 起動方法への影響 | 備考 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ディレクトリ単位のシンボリックリンク | ✅ | ◎<br>`rename` がリンク先ディレクトリ内で完結する | ◎<br>そもそも壊れない | ◎<br>変更不要 | `themes/` `grammars/` `plugins/` も同時に管理下へ入る |
| `config.json` 単体のシンボリックリンク | | ×<br>保存のたびに切れる | ○<br>`ls -la` で実ファイル化が見える | ◎<br>変更不要 | 従来の方式 |
| `config.json` のハードリンク | | ×<br>`rename` で inode が分離する | ×<br>両方が通常ファイルに見え、乖離が表面化しない | ◎<br>変更不要 | |
| `--config <PATH>` でリポジトリ内を直接指定 | | ×<br>読み込み専用の経路で、保存先は `~/.config/fresh` のまま | ×<br>読み込み元と書き込み先が黙って乖離する | ×<br>全ての起動箇所へフラグを通す必要がある | 設定パス用の環境変数はなく、macOS では `XDG_CONFIG_HOME` も参照されない |

#### 意思決定した理由

判断軸は「fresh が設定を保存しても管理状態が壊れないこと」と「壊れた場合に気付けること」の 2 点。ハードリンクと `--config` はどちらも乖離が表面化せず、リポジトリ側が古い内容のまま放置される危険が最も大きい。ディレクトリ単位のリンクは `rename` の影響をリンク先の内側に閉じ込められるため、破損そのものが起きない。生成物を除外する手間は生じるが、`fresh/.gitignore` の数行で済む。

## Note

- 設定 UI から設定を変更すると、このディレクトリの `config.json` が直接書き換わり、作業ツリーに差分として現れる。意図した変更かを確認してからコミットする。
- fresh が起動時に生成する `types/` と `tsconfig.json` は `fresh/.gitignore` で除外している。
- リンクの実体はディレクトリなので、`README.md` と `.gitignore` も `~/.config/fresh` 配下に見える。fresh はこれらを読まないため動作へは影響しない。
